# v3.2 — "Pitch-Ready" Pass — Design Spec

**Date:** 2026-07-04 · **Ships to:** `main` as `v3.2` · **Team 4 — IT2021, UC**

## Goal

Take v3.1 from "polished student project" to "credible to pitch to the UC
business school as a real campus venture." The audit found the UI is already
strong; this pass closes the last-5% defects, adds the business narrative
in-product, ships one headline feature, and produces a founder pitch asset.

Four tracks, built and committed one by one.

## Track A — Demo-flawless polish

Nine self-contained fixes surfaced by the v3.2 UX/UI audit. Each is low-risk.

1. **Browse inputs controlled** — course/min/max use `defaultValue` and desync
   when a chip is removed (URL clears, field keeps old value). Make them
   controlled + reset on chip removal. (`browse/BrowseFilters.tsx`)
2. **Success/"Sold" badge AA contrast** — `text-success` on `bg-success/10` is
   ~3:1 at 12px. Darken text or use a solid chip. (`ui/Badge.tsx`)
3. **ListingCard structure** — button-inside-anchor is invalid HTML; make the
   card a wrapper with an overlay link + sibling favorite. Product image
   `alt = listing.title` (currently `alt=""`). (`ListingCard.tsx`, `FavoriteButton.tsx`)
4. **Publish from Drafts** — draft rows offer only Edit/Delete; add a one-click
   Publish. (`my-items/ItemRowActions.tsx`)
5. **Normalize page `<h1>`** — Saved/Notifications/Moderation/Funnel drift to
   `text-lg`/`text-xl`; normalize all top-level titles to `text-2xl`.
6. **Messages `📍` → `PinIcon`** — the only emoji in an SVG icon system;
   renders per-OS. (`messages/page.tsx`)
7. **Moderation `loading.tsx`** — the one route doing DB work with no skeleton.
8. **Distinct EmptyState icons** — `EmptyState` accepts `icon`; call sites omit
   it, so every empty state shows the same cube. Pass real icons.
9. **Sell type-card selected-state** — selecting sets step immediately so the
   `border-accent` highlight never renders; let it show briefly / persist.

## Track B — Public "How it works" page

New route `/how-it-works` in the `(public)` group. No auth.

- Three steps: **List it → Meet on campus → Keep it in circulation.**
- Trust model row: UC-verified · campus meetups · no fees.
- Real impact numbers via `getImpactStats()`.
- Linked from landing header + footer.

Doubles as the pitch narrative, in-product.

## Track C — Sustainability leaderboard (headline)

New route `/leaderboard`. New lib `src/lib/leaderboard.ts`. **No schema change**
— every ranking derives from existing rows (completed SELL+DONATE = "kept in
circulation", the same definition as `impact.ts`).

- **Two tabs:** *Top Bearcats* (students by items kept in circulation) and
  *By major* (which majors keep the most out of landfills — campus-rivalry /
  network-effect hook).
- Signed-in users see **"You're #N"** tying personal impact to the collective.
- Public route (social proof) + linked in app nav.
- **Privacy:** only `displayName` (already public on every listing); users with
  null `displayName` excluded from the individual board.
- **Seed enrichment:** grow the seed to ~12 users with completed listings across
  a few majors so the boards look alive in a demo.
- **Out of scope (YAGNI):** no dorm board (no dorm field exists), no new DB
  fields, no time-range toggle.

Data source: `User` has `displayName`, `major`, `classYear`. No dorm/building.

## Track D — Founder pitch one-pager

A single shareable, design-grade HTML **Artifact** (built with `artifact-design`):
problem → solution → UC-campus wedge → real impact/traction numbers → business
model (free now; future featured-listings / partnerships) → go-to-market
(move-out season, orientation) → team. The app is the proof; this is the leave-behind.

## Sequence & verification

A → C (lib TDD, then page, then seed) → B → D. Each track: typecheck + `vitest`
green before commit. Leaderboard lib gets unit tests. Avoid `npm run build`
while a dev server runs (known `.next` corruption gotcha).
